# Сборка презентаций // из банка слайдов
подзаголовок: Slidecraft BITOBE · итоги первого этапа
для: команды BITOBE
дата: 3 ноября 2026
обложка: 4
заметки: Мы запустили систему, которая собирает презентации BITOBE из готовых слайдов банка по запросу обычными словами. Покажу, какую задачу она решает, как устроена, что сделано на этапе и куда её развивать.

## Задача | КП собирают вручную: это долго, легко ошибиться, есть риск для данных клиентов
тип: карточки
- Долго искать: Нужный слайд приходится искать листанием в банке из 181 слайда.
- Легко ошибиться: В банке есть копии и варианты одной мысли: непонятно, какой слайд брать.
- Риск для клиента: Слайд с данными одного клиента может попасть в презентацию другому.
вывод: Цель: собирать КП и выступления из готовых слайдов быстро, по смыслу и без риска для данных клиентов.
заметки: Исходная ситуация: банк большой, нужный слайд ищут вручную, есть копии и варианты одной мысли, часть слайдов содержит данные конкретных клиентов.

## Решение | Поэтому мы запустили систему: запрос обычными словами превращается в готовый PPTX из банка
тип: цифры
лид: Запрос словами → подбор по смыслу → карта слайдов → «ок» человека → готовый PPTX
- 181: слайд с карточкой смысла
- 2: команды: подбор и правка каталога
- 0: сборок без согласия человека
заметки: Слайды не перерисовываются: агент только выбирает и ставит их по порядку. Человек всегда видит карту слайдов до сборки.

## Как это работает · схема 1 | Подбор проходит 8 шагов, и без «ок» человека ничего не собирается
тип: цепочка
акцент: 6
- Запрос: Обычными словами: для кого, зачем, сколько слайдов
- Уточнение: Если неясны аудитория, цель или длительность — до 3 вопросов
- Сюжет: 5–9 тезисов: от проблемы клиента к следующему шагу
- Подбор в два прохода: Кандидаты по короткому индексу, затем выбор по полным карточкам
- Карта слайдов: Тезис, слайд, почему он, что поменять; пробелы и риски
- Стоп: Человек правит карту или пишет «ок». Без «ок» сборки нет
- Сборка и проверка: Слайды копируются из банка и сверяются с картой по картинкам
- Готово: PPTX в папке decks и список правок руками
текст: Команда /podbor · шаги 1–6 агент делает сам, на шаге 7 — обязательная остановка
заметки: Подбор идёт в два прохода: по короткому индексу отбираются кандидаты, затем по полным карточкам выбирается слайд под каждый тезис. Если под тезис ничего нет, агент пишет «пробел», а не подставляет слабый слайд.

## Как это работает · схема 2 | Подбор работает по смыслу, потому что у каждого из 181 слайда есть карточка в каталоге
тип: схема
- A1-2 Банк слайдов: `library/bank.pptx` // 181 слайд — единственный источник для сборки // Рядом: превью и текст каждого слайда
- B1 Каталог: `catalog.json` // Карточка на слайд: тезис, когда ставить, данные клиента, дубли
- B2 Индекс и страница: `index.jsonl · app/index.html` // Индекс для агента, каталог с превью для людей
- C1 Правка каталога: `/obnovit` // Правит карточки, проверяет каталог, пересобирает индекс
- !C2 Подбор и сборка: `/podbor` // Читает индекс и карточки, собирает PPTX из банка
связи: A1->B1 описан; B1->B2 собирается; C1->B1 правит; B2->C2 читает
примечание: Всё хранится в закрытом репозитории GitHub. Изменения в общий банк — через pull request и ревью владельца банка.
заметки: Слева — банк, в центре — каталог: карточка смысла на каждый слайд, из него собираются индекс для агента и страница для людей. Справа — две команды.

## Как это работает · схема 3 | С каждой правкой каталог становится точнее для всей команды
тип: цепочка
акцент: 4
- Замечание: «Этот слайд не про это» — при подборе или в каталоге
- Правка: Команда /obnovit меняет только названные поля карточки
- Проверка: Скрипт проверяет каталог и пересобирает индекс и страницу
- Ревью: Владелец банка принимает правку на GitHub
вывод: Каждая правка одного человека делает следующий подбор точнее для всей команды.

## Правила системы | Пять правил защищают качество и данные клиентов
тип: список
- Стоп перед сборкой: Ничего не собирается без явного «ок» по карте слайдов.
- Слайды не перерисовываются: Агент только выбирает и ставит по порядку. Чего нет в банке — отмечает как пробел.
- Данные клиентов: Слайд с данными другого клиента попадает в карту только с пометкой «обезличить».
- Один слайд из группы дублей: Копии и варианты одной мысли не попадают в презентацию вместе.
- Каталог — общий ресурс: Правки карточек — через команду и проверку. Клиентские презентации в репозиторий не попадают.
