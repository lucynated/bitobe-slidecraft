# Slidecraft BITOBE — правила проекта

Проект собирает презентации BITOBE из готовых слайдов банка. Подбор идёт **по смыслу**, по карточкам каталога. Человек всегда согласует карту слайдов до сборки.

## Что где лежит
- `library/bank.pptx` — банк слайдов (181 слайд). Единственный источник слайдов для сборки. Номер слайда = номер в этом файле.
- `library/catalog.json` — каталог: карточка на каждый слайд (`slides`) и группы дублей и вариантов (`duplicates`). Схема — `taxonomy.md`.
- `library/index.jsonl` — короткий индекс, одна строка на слайд. Генерируется, руками не править.
- `library/slides/img/s-NNN.jpg` — превью, `library/slides/text/NNN.md` — текст и заметки докладчика.
- `library/examples.json` — тексты и примеры подбора для страницы каталога.
- `library/sources/` — шаблон 2025 и типовые слайды 2026. **Пока не каталогизированы и в сборке не участвуют.**
- `app/index.html` — страница каталога. Генерируется из `app/template.html`.
- `decks/` — карты слайдов (`.md`) и собранные презентации (`.pptx`).
- `docs/` — схема v2 для расширения на архив КП из CRM и промпт этого этапа.

## Команды
- `/podbor <запрос>` — подбор, карта слайдов, после «ок» — сборка и проверка.
- `/obnovit <правка>` — правка карточек, проверка каталога, пересборка страницы и индекса.
- `python3 scripts/build_deck.py --from decks/<карта>.md -o decks/<карта>.pptx` — сборка по карте.
- `bash scripts/render.sh decks/<файл>.pptx` — картинки для проверки.
- `python3 scripts/check_catalog.py` — проверка каталога. Запускать перед каждым коммитом каталога.
- `python3 scripts/build_page.py` — пересборка страницы и индекса.

## Правила
1. **STOP-GATE.** Ничего не собирать без явного «ок» по карте слайдов.
2. **Слайды не перерисовывать.** Только выбор и порядок слайдов банка. Сложные схемы не перестраивать: если содержание не ложится, это «пробел» в карте.
3. **Данные клиентов.** Слайды с `client_data` ≠ «нет» не ставить в чужие презентации без пометки «обезличить» в карте.
4. **Дубли.** Из группы в `duplicates` в одну презентацию идёт один слайд. Слайды-дубли с `keep` = другому слайду не предлагать.
5. **Каталог — общий ресурс.** Править `library/catalog.json` только через `/obnovit` или с последующими `check_catalog.py` и `build_page.py`. Коммитить с понятным сообщением, пушить только с согласия человека.
6. **Модели.** Сборка и правки PPTX — Opus. Массовое написание карточек для новых слайдов — субагенты на Sonnet пачками по 40, выборочная проверка — Opus.
7. Не коммитить клиентские презентации из `decks/` без согласия: по умолчанию `.pptx` в `decks/` игнорируются git, кроме демо.

## Как добавить новые слайды в банк (следующий этап)
Сейчас банк — один файл. Для подключения КП из CRM и типовых слайдов используется `docs/PROMPT_crm_mvp.md` и схема `docs/taxonomy_v2.md`: несколько исходных файлов, дубли между ними, источник и стадия сделки в карточке. При переходе `build_deck.py` нужно научить собирать слайды из нескольких файлов.
